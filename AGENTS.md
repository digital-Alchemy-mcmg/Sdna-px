# Repository agent governance

## Authority

- The operator owns search intent, architectural decisions, taxonomy approval, calibration, production promotion, and acceptance.
- Codex may build, test, document, and report this repository's deterministic workbenches. Codex may not redefine the meaning or authority of Scout stages.
- A1 compiles operator-authorized scope. It never dispatches a runner.
- A2 executes only through an explicitly selected adapter and preserves the unmodified return.
- A3 indexes evidence and initializes the Traveling Envelope. It does not score or accept evidence.
- A4 verifies integrity and freezes an inspection package. It does not make substantive acceptance decisions.
- The A5 workbench validates and records decisions. The independent A5 reasoner supplies substantive judgment without write access to evidence, the envelope, or B1.
- B1 independently controls MARA admission. A5 cannot force admission or execute B1.
- MARA B1 and B2 remain candidate-blind. B3 may discover and select actual candidate atoms but cannot declare proposition truth. B4 independently audits only B3-selected atoms. B5 is outside this repository build boundary.

## Prohibitions

Agents must not invent evidence, taxonomy assignments, search criteria, source material, reasoner findings, or missing contract fields. They must not silently repair evidence, broaden certified scope, overwrite earlier receipts, hard-code credentials, invoke live runners or reasoners during ordinary tests, or present simulations as live validation.

No agent may mutate frozen A4 submissions, original sidecar evidence, or prior A5 dispositions. Rejected and held findings remain append-only. Scope changes return to the operator and require recompilation. External writes, deployment, merge, production certification, and configuration promotion require explicit operator authorization.

No agent may alter target requirements to favor the candidate, alter candidate truth to favor the target, treat titles as proof, cite unselected evidence in B4, satisfy a hard gate with a narrower claim, or execute B5 from the Segment B workbench.

## Required practice

Before editing, inspect current contracts, tests, status, and authority assumptions. Record contradictions and missing authoritative dependencies. Keep core logic importable and notebook cells orchestration-only. Use explicit adapters and configuration slots for external systems. Opening a notebook must have no live runner, network, reasoner, or external-write side effects.

Fixtures and simulation receipts must be labeled as such. Development receipts remain distinct from production evidence. Every release package must be attributable to frozen hashes, versioned criteria, and an independently identifiable reasoner response. Run the existing suite and the Scout workbench suite before reporting completion.
